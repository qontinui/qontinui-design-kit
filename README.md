# qontinui-design-kit

Design-language compiler, exclusive Tailwind v4 theme, state-complete component kit and specimen for Qontinui-built products. MIT.

Status: Phases 1 to 6 of plan `2026-11-19-the-visual-system-is-prose-no-build-step-compiles-and-the-project-template-ships-no-design` (the repo, three probes, the compiler core, the token-package adapter, the rule-bearing guide with budgets and thresholds, the state-complete kit slice with its specimen and state check, and the generated component index). The template wiring is a later phase.

## Use

```sh
npm install github:qontinui/qontinui-design-kit#<tag-or-sha>   # prepare builds dist/
npx design-kit compile            # design/language.dtcg.json -> src/design/{tokens.css,tokens.ts,theme.css,compile-report.json}
npx design-kit compile --check    # exit 1 when the committed outputs differ from a fresh compile
npx design-kit status             # each group's state and the next undeclared group
npx design-kit diff --base origin/main      # LOOSENED lines for budgets and thresholds that moved toward permissive; exit 0 always
npx design-kit lint-classes src             # arbitrary-value classes and inline literal colours or lengths in .tsx files
npx design-kit specimen [--check]           # specimen.html: every component x variant x state, plus a design-system board
npx design-kit check-states specimen.html   # forced-state measurement through the published exec door -> state-coverage.json
npx design-kit validate-guide src/design/<app>.styleguide.uibridge.json specimen.html
npx design-kit validate-guide <guide> http://localhost:3001/route --storage-state auth.json --json out/route.json   # an authed route, machine-readable
npx design-kit index [--check]              # the component index between the markers in CLAUDE.md
```

Exit codes: 0 ok, 1 drift (`--check`) or findings, 2 the source was refused or the command was misused, 3 UNKNOWN (the instrument could not measure). A `validate-guide --json` report that cannot be written exits 2 after the verdict is printed.

## The source: `design/language.dtcg.json`

A DTCG 2025.10 document. Every leaf carries `$extensions.qontinui.source`, one of:

| source | meaning |
|---|---|
| `declared` | the owner or the tenant's visual system states it |
| `resolved(<package>@<ref>)` | read from an imported token package; only an import produces it, a source file cannot state it |
| `authored(<notification_ref>)` | structural only (a spacing scale, a density budget, a state contract); without a ref it is listed as `unverified-provenance`, stage `draft` |
| `derived(<rule>)` | computed from a stated rule (`modular-scale`, `spacing-multiple`) with its inputs recorded |
| `undeclared` | a compile state: no value is emitted and the report says so; a default is never substituted. It may say why: `"$extensions": { "qontinui": { "source": "undeclared", "reason": "..." } }` puts the reason in the report's `undeclared` list (a `reason` on any other source is refused) |

Groups: `color`, `type`, `space`, `layout`, `motion`, `states`, `budgets`, `thresholds`, `imagery`, `exceptions`.

Identity values (every `color` leaf, `type.family.*`, `imagery.style.*`) can never be `authored`: the compiler refuses the whole source and names the policy clause `ux-priorities/style-is-resolved-from-the-tenants-declared-visual-system`.

An undeclared identity renders as a CSS **system keyword** (`Canvas`, `CanvasText`, `ButtonFace`, `GrayText`, `Highlight`, `system-ui`, ...) plus state deltas (`color-mix(in oklab, CanvasText 8%, Canvas)`). Those are the browser's values, not a palette the fleet chose. The report says `identity.state: "undeclared"` and lists the roles that fell back.

Resolve first: `"$extensions": { "qontinui": { "import": [{ "package": "@qontinui/design-tokens", "ref": "415be45", "groups": ["typeScale", "durations"] }] } }` reads the built package (at a git ref, or the installed version when `ref` is absent) and labels every leaf `resolved(@qontinui/design-tokens@<ref|version>)`. A source never copies a hex value. The web type scale needs a declared surface unit (`type.unit`, a number) because the package scale is drawn at a 1080px reference frame; with none, `type.scale` stays `undeclared`. The groups are `color`, `fontFamilies`, `typeScale`, `fontWeights` (`type.weight.*`), `lineHeights` (`type.leading.*`), `letterSpacings` (`type.tracking.*`, read only as `<number>em` and emitted in `em`), `durations`, `easings` and `reducedMotion`. A group the package does not export stays `undeclared`. Env: `DESIGN_TOKENS_REPO` (where to clone from), `DESIGN_KIT_CACHE` (where built refs are cached).

The outputs of Phase 2 are `tokens.css` (`--dk-*` custom properties), `tokens.ts` (typed `tokens` / `vars` constants), `theme.css` (a Tailwind v4 `@theme inline` block that begins `--*: initial`) and `compile-report.json`. Use `@import "tailwindcss"; @import "./design/tokens.css"; @import "./design/theme.css";`. A theme does not stop arbitrary values (`bg-[#f00]`); a later phase ships `design-kit lint-classes` for that.

Craft bands (`src/craft/arithmetic.ts`, `draft`, listed in the report as `out_of_band`, never an error): body line height 120% to 145%, measure 45 to 75 characters, interface motion 100 to 300 ms (a zero duration is a step), contrast as an OKLCH lightness difference of at least 0.40, one shadow light source.

## Guide, budgets and thresholds (Phase 4)

`compile` also writes, beside the tokens:

- `<app>.styleguide.uibridge.json`, a `StyleGuideConfig` (ui-bridge `specs/style-types.ts`) generated from the compiled tokens and the kit's own component data: a colour is a role of the palette, a radius is on the scale, a heading's size is a declared step above the body step, and each kit component declares its state matrix through the `--dk-kit-states` custom property (a hand-rolled button declares none and fails `button-state-declaration`). A rule whose group is undeclared is omitted, not invented. Token values are written in computed form where statically known (a hex colour is `rgb(r, g, b)`, a `rem` length is `px` at the 16px root, and so is an `em` font size, spacing step or radius, as in 0.1.x); an `em` tracking value or line height stays `em`, because its px depends on the element's font size. A shadow whose colour is an alias lists the resolved colour (in `tokens.css` it reads the colour's variable). `validate-guide` canonicalises every other spelling (`Canvas`, `color-mix(...)`) through the browser before it runs the published `validateElement` over the page's `getDesignSnapshot` elements. Exit 1 on any `error` rule failure. A page whose linked stylesheet did not load exits 3 `unknown(stylesheet-missing): <paths>`: a verdict over browser defaults is not a verdict on the design. "Did not load" is a `.css` 404 the kit's file server answered, or an enabled `<link rel="stylesheet">` or an `@import` whose request the page's resource timing reports at status 400 or above, or with a content type that is not `text/css` (a dev server answering a missing `.css` path with its HTML shell), or with a visible status, an empty reported content type and no rules (a sheet sent as `application/octet-stream`, same-origin or with CORS, which Chromium refuses and reports with no type; an empty sheet sent with no Content-Type reads the same way, toward UNKNOWN), or a link with no sheet despite a response, or a link with an empty `href`, or an `@import` with no sheet despite a response; a link with no `href` attribute requests nothing and is not counted. Chromium gives a 404'd or refused sheet an empty, non-null `sheet`, so the timing entry is what catches it on a URL target. A sheet is named by its decoded path on the page's own origin, and by origin and path on another, so a signed sheet URL's query stays out of the reasons and the report. A favicon, image or font 404 does not count, and a `disabled` link is skipped; a `.css` request that fails counts even when no applied sheet asked for it (a `<link rel="preload" as="style">` to a missing file): the kit's own server records it for a file target, and the page's resource timing for a `.css` a `<link>` requested on a URL target, so such a page reads UNKNOWN either way. A link or `@import` with no sheet and no response yet, or with an empty sheet and no recorded response (a 404'd sheet whose timing entry the page cleared or the buffer dropped looks exactly like it), reads `unknown(stylesheet-pending)`, and a sheet fetched from another origin without CORS (the link has no `crossorigin` attribute, its server sends no `Access-Control-Allow-Origin`, or it is a cross-origin `@import`, which the browser always fetches without CORS) reads `unknown(stylesheet-unreadable)`: both exit 3, because neither can be read as loaded. A page that loads a third-party sheet that way gets no verdict until the sheet is linked with `crossorigin` from a server that allows it; a cross-origin `@import` is never readable. The check runs before the page's elements are read and again after, so a sheet still loading at the first read is `pending` even if it loaded by the second. It sees only what resource timing records: a cross-origin sheet fetched without CORS reports status 0 and no content type, a page with more resources than the timing buffer holds (250 by default) can lose entries (for a file target the kit's own server still records a `.css` 404), the `@import`s of an unreadable sheet cannot be walked, sheets inside a shadow root are not read, a sheet for another medium (`media="print"`), an alternate sheet (`rel="alternate stylesheet"`) or a prefetched `.css` is checked like any other, and a quirks-mode page (no doctype) that applies a same-origin `text/plain` sheet still reads it as not loaded (UNKNOWN, never a pass). An `@import` naming a sheet above it (a cycle, which the browser does not follow), or one whose `supports()` condition is false (fetched, never applied, whatever its response), is not counted by the page-side check (on a file target the kit's server still records any `.css` 404, so a false-condition import of a missing file reads UNKNOWN there), and nested imports are followed to any depth. A link whose `type` is not CSS by its MIME essence (`text/css; charset=utf-8` is CSS) is never fetched and is not counted. A page the browser ended on at another origin or path than the target (a redirect: an expired `--storage-state` sent to the login page, or a trailing slash added or dropped) is `unknown(redirected)` (exit 3), naming the target and the page it ended on by origin and path; the query and fragment are neither compared nor printed in the reason (so a hash-routed app's redirect from `/#/dashboard` to `/#/login` is not seen) (a callback's code or token stays out of logs), and paths are compared decoded, so a path the browser escapes (`http://host/a|b`, requested as `/a%7Cb`) is the same page. The report's `target` field is the target as given. A file target resolves against the current directory; the guide, `--json` and `--storage-state` resolve against `--root`. `--storage-state <file>` hands the wrapper a Playwright storageState for an authed route (a file that is unreadable, or is not a JSON object with `cookies` and `origins` arrays, exits 2). `--json <file>` writes the report (`schema: 1`): `elements`, `rules`, `failures` (each with rule and element), `failuresByRule`, `unmatchedRules`, `stylesheets` (`requested`, `failed`, `unreadable`, `pending`), `instrument`, `exitCode`, and `unknown` (the `unknown(...)` reason on exit 3, else null). Fields a run that stopped before evaluating never reached are null, `failures`, `failuresByRule` and `unmatchedRules` included, so such a run never reads as "nothing failed"; `elements` is null too when the elements read were not the target's whole list (a redirect, a truncated snapshot) (an `unknown(no-rule-matched)` run did evaluate, and lists its empty results). Every `validate-guide` run with `--json`, including one refused with exit 2 at argument parsing, first removes any earlier report at that path (the command is read as the first bare word, so an argv that puts another word before `validate-guide` clears nothing, and nor does one in which `--root` or `--json` has no value or an empty one, such as an unset `"$ROOT"`, nor one spelling either `--root=<dir>` or `--json=<file>`, which is refused as an unknown option: such a run names no report it could resolve. A misspelt option such as `--rooot <dir>` cannot be told from any other unknown option, so the report is resolved against the current directory then). A `--json` path that names the guide, a file target, the `--storage-state` file or any other bare word (a word a mistyped option shifted; each resolved against `--root` and the current directory), or a directory, is refused with exit 2 and left as it is, and so is any other file that is not an earlier report (a JSON object with `schema: 1` and a numeric `exitCode`): only a report is ever removed. A path that is not a regular file (a pipe, `/dev/null`) or an empty file is not read: the report is written into it after the verdict, so a FIFO needs a reader, or the run waits there. The run's own stdout (`--json /dev/stdout`, whether stdout is a file or a pipe) is refused with exit 2, because it carries the verdict.
- `conditions.css`, the kit's conditional rules (a kit rule with `when: "wide"` or `when: "short"`) under this project's own conditions: `wide` is `@media (width >= <layout.breakpoint.md>)` and `short` is `@media (height < <layout.shell.bar ÷ budgets.shell.max_pinned_share>)`, the breakpoint written as the source states it and the quotient at 12 significant digits (never rounded to a fixed number of decimals), each written only in the `@media` prelude (a custom property never applies in a media feature, so the condition is compiled, not read from `tokens.css`). Every declaration still reads `var(--dk-*)`. A source missing a leaf a condition needs gets no rule for that condition, and `compile-report.json` lists the leaf `undeclared` (whether or not a kit rule names the condition yet) and the condition under `conditions`. A stated value that cannot make a condition (a `max_pinned_share` outside (0, 1], an alias, a bar that is not a `px`, `rem` or `em` length (the units a guide breakpoint takes; `48%` and `48foo` are not; a breakpoint in any other unit is refused by the guide), a quotient that is not a positive finite length) never fails the compile: the condition reads `invalid` with its `reason`, and no rule is emitted for it. Load it after the kit's stylesheet (`kitCss()`): a conditional rule overrides a base rule of equal specificity only by coming later. A breakpoint in `theme.css` is likewise the source's literal (`--breakpoint-md: 768px`), so Tailwind's `md:` applies; 0.2.x wrote `var(--dk-layout-breakpoint-md)` there, which no media query can read.
- `design-budgets.json` (the `budgets` group and the craft bands as `draft` thresholds) and `visual-system.thresholds.json` (the `thresholds` group and `imagery.threshold.*`). Each entry carries `value`, `source` (`declared`, `draft` or `undeclared`), `check_version` (the first 16 hex of the sha256 of the check name, a newline and the JSON value) and `stage`. The two imagery thresholds `domain_spec/visual-system` lists as undeclared (`image_resolution_sufficient.min_effective`, `image_palette_within.max_delta_e`) are emitted as `undeclared` with a null value, never 0, unless the source states them.

**Stage is computed (D5).** `declared` for a declared or resolved value; `draft` for an authored or derived one; `shown` when `design/threshold-evidence.json` (`{"records":[{"check","check_version","injected_violation","failed":true}]}`) holds a failing record for that exact `check_version`. Changing the value changes the hash, so the record stops matching and the stage falls back to `draft` on the next compile. The compiler never reads a merge state; no stage is a gate. A leaf's `$extensions.qontinui.bound` (`max`, `min` or `none`) says which way it loosens; without it a leaf named `max`/`max_*` is a max bound and `min` likewise.

**A loosening is marked, never failed (D6).** `diff --base <ref>` compares the base's committed `design-budgets.json` and `visual-system.thresholds.json` with a fresh compile and prints `LOOSENED <check> <old> -> <new>` (a raised `max`, a lowered `min`, a removed or withdrawn bound); a change in a bound with no declared direction prints `MOVED`. It appends the same list to `$GITHUB_STEP_SUMMARY` when set and exits 0.

**`lint-classes <dir>`** closes the gap Probe 1 recorded: Tailwind v4 emits arbitrary values whatever `--*: initial` says. It reports, with file:line:column, arbitrary-value classes (`bg-[#f00]`, `p-[13px]`), arbitrary variants, and inline literal colours and lengths in `.tsx` files (comment lines are skipped). A line carrying `design-kit-exception: <id>` where `<id>` is an `exceptions` entry of the source is waived; an unknown id waives nothing and is itself a finding. Exit 1 on findings.

## The kit slice, the specimen and the state check (Phase 5)

`defineComponent({ name, props, states })` stores a component's states as data from the closed list `default | hover | focus-visible | active | disabled | loading | error | selected`. The slice is `Button`, `TextInput`, `Select`, `Checkbox`, `Switch`, `Tabs`, `Dialog` and `DataTable` over Radix (or the native element), plus the working-screen pattern `RecordListPage`, whose `empty`, `loading`, `error` and `filteredEmpty` props are required (omitting one is a compile error, proved by a `@ts-expect-error` fixture). Since 0.3.0 a second pattern, `AppShell`, is in the slice (below). The kit ships no skin: every declaration in `kitCss()` reads `var(--dk-*)` (a test reads every rule for a literal), so a source must provide the tokens the kit reads (`kitTokenContract()`; `design/language.dtcg.json` in this repo is a complete example whose identity groups are undeclared and whose structural groups are authored). Disabled is visibly different from enabled in every control. Components are imported from the package root; `@qontinui/design-kit/specimen` exports `generateSpecimen`. React 18 or 19 and the Radix packages are peers.

`design-kit specimen` writes a static `specimen.html` (no script): one cell per component, variant and state (56 for this slice), a design-system board of the compiled roles, scale, spacing, radius and motion, the `RecordListPage` states, `AppShell` in both variants (its narrow form: the specimen loads no `conditions.css`), and, when identity is undeclared, `data-design-identity="undeclared"` on `<html>` with a banner.

`design-kit check-states <url|file>` drives `ui-bridge-inject --exec-stdin` (the published `@qontinui/ui-bridge-wrapper`) with `getElementStateStyles` and writes `state-coverage.json`: per cell, `changedProperties` (a count), whether every changed value is token-derived, and `complete`.

- `hover` and `active` are forced on the cell's element. `disabled`, `loading`, `error` and `selected` are carried by the attribute the component reads, and the cell is compared with the same variant's default cell (visual properties only).
- **Token-derived** is decided by value: the door reports computed values, so a changed value is token-derived when each colour or length in it equals the computed value of some `--dk-*` custom property in the page (read through a probe element by `pageEvaluate`). A literal that equals no token is a `non-token-delta` finding; a literal that happens to equal a token value passes, which is the limit of the method.
- A changed property whose value has no colour or length (`cursor`) is ignored as `keyword`; one whose value contains `none` (`outline: 3px none <colour>`, which paints nothing) is ignored as `inert`. Both are listed in `ignoredProperties`, not counted.
- A measured cell with no counted change is a `no-delta` finding.
- `focus-visible` is not emulated by the published door at `@qontinui/ui-bridge` <0.56.0 (Probe 3; 0.56.0 emulates it, see 0.2.1 below, but `check-states` does not use that yet): those cells are `unknown(focus-visible-not-emulated)`, never a pass. Any other unknown (the door answered fewer steps than asked, an element is missing) exits 3.
- Token values are known only when every linked stylesheet loaded (the same check `validate-guide` runs) **and** the page declares a `--dk-*` token other than the kit's own `--dk-kit-states`. Otherwise every cell the door measured is `unknown(stylesheet-missing): <paths> did not load`, `unknown(stylesheet-pending): …`, `unknown(stylesheet-unreadable): …` or `unknown(no-token-values)` (or `unknown(instrument-cannot-read)` when the door did not answer the check), and `state-coverage.json` carries `stylesheets` (`requested`, `failed`, `unreadable`, `pending`).

## The app shell: `AppShell`

`AppShell` is the kit's second working-screen pattern (plan `2026-11-26-the-app-shell-is-never-derived-from-what-every-role-does-on-every-page`, Phase 3): the default shell of a new product, not a standard. A tenant's declared design (a customer's Figma, a design system of its own) replaces it, and the shell itself, what it holds and which role sees which entry, is derived as a surface under the tenant's `ux-priorities`, from what every role does on every page.

```tsx
<AppShell product="Shop" sections={sections} can={(p) => me.permissions.includes(p)} current="orders"
  account={{ name: me.name, role: me.roleLabel, items: [{ id: "out", label: "Sign out", href: "/logout" }] }}
  cart={{ label: "Cart", href: "/cart", count: 2 }}>
  {page}
</AppShell>
```

- **Forms.** At and above the source's `layout.breakpoint.md` (the compiled `wide` condition), `variant: "sidebar"` (the default) puts the navigation beside the content, in view while the content scrolls and scrolling within itself when it is taller than the viewport; `variant: "topbar"` pins one row of one control's height (`layout.shell.bar`) with the entries inline. Below it, a fixed bar of one control's height holds the product name, the account and cart controls and the menu control (`aria-expanded`, `aria-controls`), and the entries open in a menu panel. Scroll padding equals the pinned height, so a focused control is never hidden behind the bar. Where the bar would take more than `budgets.shell.max_pinned_share` of the height (the `short` condition, as at a high zoom), it unpins.
- **Permissions.** `sections` group the entries; `can(permission)` decides each `requires`. A denied entry is not rendered, or, with `whenDenied: "disable"` (which then requires a `reason`), rendered with `aria-disabled="true"` and its reason as visible text. A denied or emptied section is not rendered.
- **Account and cart.** The account control always shows the role; the name shows in it at the wide form and otherwise in its menu, beside the app's `items`. Nothing is shown for an absent field. The cart slot renders only when `cart` is passed.
- Every declaration reads `var(--dk-*)` (`layout.shell.bar` and `layout.shell.sidebar` among them); the width and height switches are `wide` and `short` rules, so they reach a page only through the project's compiled `conditions.css`, which the page must load after `kitCss()`. The tests drive the component through the UI Bridge exec door at 1280 x 800, 360 x 740, 360 x 320 and 1280 x 400 (`test/app-shell.test.js`).

## The component index (Phase 6)

`design-kit index` writes, between `<!-- design-kit-index:start -->` and `<!-- design-kit-index:end -->` in the project's `CLAUDE.md` (appended when there are no markers), one entry per component: its JSDoc summary and `@use` / `@avoid` notes, its props read from the TypeScript source or declarations (the compiler API), its variants and states from the component data, and the tokens it reads. `index --check` exits 1 on drift or missing markers; a hand edit between the markers is overwritten by the next `index`. The index of the slice is at most 8,192 bytes, asserted as a literal; a component that pushes it past the limit gets trimmed JSDoc, never a higher limit. `typescript` is a peer of this verb.

Peers for the verbs that measure: `@qontinui/ui-bridge-wrapper` `>=0.12.0 <1`, `@qontinui/ui-bridge-headless` `>=0.7.0 <1`, `@qontinui/ui-bridge` `>=0.54.0 <1` (all optional; CI tests `0.56.0` and the `0.54.0` floor) and Playwright's Chromium (`npx playwright install chromium`). The tests that need Chromium skip locally with `unknown(instrument-cannot-force)` when it cannot run and fail under `CI`.

## Probe record (plan Phase 1), measured 2026-11-19

Node v24.19.0, npm 11.17.0, Chromium via Playwright 1.65.1.

**Probe 1, the exclusive theme** (`test/probe-exclusive-theme.test.js`, `tailwindcss` / `@tailwindcss/postcss` 4.3.x). Confirms every plan assumption. With `@theme { --*: initial; --color-surface: ...; --spacing: 4px }`: `bg-surface` and `p-3` are emitted; `bg-red-500`, `text-lg` and the `md:` variant are not. Without `--spacing`, `p-3` is not emitted. Arbitrary values (`bg-[#f00]`, `p-[13px]`) ARE emitted regardless. No plan assumption was contradicted, so Phase 2 emits breakpoints and the spacing base explicitly from the source. One addition: the compiler writes `@theme inline` and the theme variables read `var(--dk-*)`, which is why `tokens.css` must be imported too.

**Probe 2, delivery** (`test/probe-git-dependency.test.js`). Arm chosen: **`prepare` builds `dist/` on a git install; no tracked `dist/`, no registry**. `npm install github:qontinui/qontinui-design-kit#<sha>` was run against the real pushed repo with npm 11.17.0 at `2b5773de59d46066c71fbae598ba981788542f7f`; `dist/` was built and `import('@qontinui/design-kit')` loaded. Note: npm 11 prints `npm warn allow-scripts ... @qontinui/design-kit@0.1.0 (prepare: npm run build)`, a warning only on this version (the script still ran). If a later npm turns it into a block, the fallback in the plan applies: a tag whose commit carries `dist/`. The in-repo test installs a one-commit copy of the HEAD tree through a local `git+file://` URL (a CI checkout is shallow) so it holds before anything is pushed.

**Probe 3, the exec door** (`test/probe-exec-door.test.js`). `@qontinui/ui-bridge-wrapper@0.12.0` (with `@qontinui/ui-bridge@0.54.0`), `ui-bridge-inject --exec-stdin`, action `getElementStateStyles`. The door measures forced states: on the fixture button, `hover` changes `color, backgroundColor, outline`, `active` changes `backgroundColor`, `disabled` changes `opacity`, and a rule-less control reports an empty change set for `hover` and `active`. Three facts differ from, or add to, the plan's wording:
- The result shape is `result.stateStyles[].diffFromDefault`, not a `changes` set.
- The door's state vocabulary is `hover | focus | active | disabled`. A `focus-visible` request is dropped (only `default` comes back): **`focus-visible-not-emulated`** (true at `@qontinui/ui-bridge` <0.56.0; 0.56.0 emulates it, see the 0.2.1 changelog). `focus` does report an `outline` change, but it cannot be told apart from `:focus`, so Phase 5 records `focus-visible` cells as `unknown(focus-visible-not-emulated)`.
- A bare `npx @qontinui/ui-bridge-wrapper@0.12.0` does NOT work: `ui-bridge-inject` needs the optional `@qontinui/ui-bridge-headless` peer (and Playwright's Chromium). This repo pins `@qontinui/ui-bridge-wrapper@0.12.0` and `@qontinui/ui-bridge-headless@0.7.0` as exact devDependencies and runs the local bin. CI provisions Chromium (`npx playwright install --with-deps chromium`).
If Chromium cannot run on a machine, the Probe 3 test is skipped with the explicit result `unknown(instrument-cannot-force)`, which is not a pass; under `CI` the same condition fails instead.

## Development

```sh
npm ci
npx playwright install --with-deps chromium
npm run typecheck && npm run lint && npm test
```

`npm test` builds `dist/` first. The adapter tests build `@qontinui/design-tokens` at `415be45` from a clone of `$DESIGN_TOKENS_REPO` (a sibling `../qontinui-design-tokens` checkout, else GitHub) into `.dk-cache/`.

### 0.2.0

Plan `2026-11-21-design-kit-compiler-gaps-and-the-unrequired-design-guide-check`, Phases 2 to 5. A minor bump under 0.x because verdicts change (D4). Each change a consumer's CI can see:

- **`validate-guide`: a missing stylesheet exits 3, not 0 or 1.** A page whose linked or `@import`-ed stylesheet did not load (a `.css` 404 from the kit's file server, or a request resource timing reports at status 400 or above or with a content type other than `text/css`, which is what catches a 404 or a dev server's HTML fallback on a URL target, or a sheet sent as `application/octet-stream` (a visible status, no reported type, no rules), or a link with no sheet despite a response) now exits 3 `unknown(stylesheet-missing): <paths> did not load`. 0.1.x evaluated the browser defaults and returned a pass or a fail. A favicon, image or font 404 does not count, and a `disabled` link is skipped; a `.css` request that fails counts even when no applied sheet asked for it (a `<link rel="preload" as="style">` to a missing file): the kit's own server records it for a file target, and the page's resource timing for a `.css` a `<link>` requested on a URL target, so such a page reads UNKNOWN either way. A link or `@import` still loading when the page is read exits 3 `unknown(stylesheet-pending)`, and a sheet fetched from another origin without CORS (no `crossorigin` attribute on the link, or no `Access-Control-Allow-Origin` from its server) exits 3 `unknown(stylesheet-unreadable)` (0.1.x evaluated both). The report gains `stylesheets: { requested, failed, unreadable, pending }` and `target`.
- **`validate-guide`: a redirected target exits 3, not 0 or 1.** When the page the browser ended on has another origin or path than the target (a redirect to a login page, a trailing slash added or dropped), the run is `unknown(redirected)`, naming that page. 0.1.x gave the verdict of whatever page the redirect served, filed under the target.
- **`check-states`: tokens behind `@import` or inside `@layer`, `@media` or `@supports` are read.** 0.1.x read only a sheet's top-level rules, so a specimen whose tokens sat in such a rule measured its deltas as non-token findings (exit 1); it now measures them (exit 0). Nesting is read down to 17 levels.
- **`check-states`: a missing token sheet, or a page with no token, is UNKNOWN (exit 3), not measured.** Token values are known only when every linked sheet loaded and the page declares a `--dk-*` token other than the kit's own `--dk-kit-states`. In 0.1.x `--dk-kit-states` alone counted as "tokens loaded", so a sheetless page was measured and usually exited 1 on `no-delta` findings. Every cell the door measured is now `unknown(stylesheet-missing)`, `unknown(stylesheet-pending)`, `unknown(stylesheet-unreadable)` or `unknown(no-token-values)` (or `unknown(instrument-cannot-read)` when the door does not answer the check); `state-coverage.json` gains `stylesheets`, and the CLI prints the unknown reason before `unknown(nothing-measured)`.
- **API: `Entry` gains a required `resolvedCss`.** The exported `buildGuide()` reads it (the guide lists resolved values), so an entry built by hand in the 0.1.x shape, with `css` only, now throws; entries from `compileSource` carry it.
- **API: the exported `canonical()` no longer converts an `em` length.** `canonical("1em")` returns `"1em"` (0.1.x: `"16px"`); the new `atRoot()` keeps the 0.1.x conversion. A consumer calling `canonical` on its own values sees the change. The exported `headingSizes()` now orders `rem` and `em` steps at 16px (0.1.x read only `px`, so a `rem` body step returned the whole scale), and reads a bare `0` body step as 0px, so the heading rule lists the convertible steps above it instead of the whole scale.
- **Guide `letterSpacings` (any `em` length) stay `em`.** 0.1.x converted `em` to px at a fixed 16px root (`0.025em` listed as `0.4px`). `rem` is still px at the 16px root, and so are `em` font sizes, spacing steps and radii, exactly as in 0.1.x. Tracking and line heights keep `em` (0.1.x listed an `em` line height in px too, e.g. `1.5em` as `24px`), so a committed guide whose source has `em` tracking or line heights drifts (`compile --check` exits 1) until it is recompiled. Breakpoints stay px: a media query resolves `em` against the initial 16px, so `48em` is `768`. A bare `0` breakpoint is accepted (0.1.x dropped it, so a source with one gains it in its guide and `compile --check` drifts once). A breakpoint stated as a bare number (`768`) or in any other unit (`50vw`) now refuses the source (exit 2, naming the leaf) for every compile-based verb (`compile`, `status`, `specimen`, `diff`); 0.1.x dropped it from the guide silently.
- **A shadow can name a colour.** An alias in a field of a shadow object, or an element of a shadow array, now resolves, provided it names a leaf of that field's type (`color` a colour; `offsetX`, `offsetY`, `blur` and `spread` a dimension; an array element a one-layer shadow; `inset` never): `tokens.css` writes the colour's variable (`var(--dk-color-glow-primary)`), the guide's `tokens.shadows` and `tokens.ts` the resolved value. 0.1.x wrote the literal `{color.glow.primary}` text and exited 0. Such an alias that names no leaf, an undeclared leaf, a leaf in a group that emits no variable, a leaf of the wrong type, or (as an array element) a shadow array of more than one layer (a string shadow is taken as written, layers and all), an alias cycle through a field, and an alias embedded in a longer string now exit 2. A shadow array renders as a comma-separated list (0.1.x refused it as "not a dimension"), `inset: true` is honoured, and a non-boolean `inset` (which 0.1.x ignored, rendering an outer shadow) or a layer with no `color` (which 0.1.x rendered as `undefined`) exits 2. The single-light-source band reads every layer of an array shadow. An alias inside any other composite value (a font-family list, a cubic-bezier) exits 2, and so does an alias embedded in any string value other than a `string` leaf (e.g. `color-mix(in oklab, {color.brand} 8%, Canvas)`); 0.1.x passed both through as literal text.
- **The adapter imports `fontWeights`, `lineHeights` and `letterSpacings`.** A source asking for them compiled to exit 2 at parse in 0.1.x; they now resolve to `type.weight.*`, `type.leading.*` and `type.tracking.*`. A `letterSpacings` value that is not `<number>em`, or a `fontWeights` / `lineHeights` value that is not a number, exits 2, naming the key. The package's 1 / 1.1 / 1.15 line heights list under `out_of_band`, not as errors. **An import with no `groups` now reads these three groups too:** a groups-less source compiled at `415be45` or later gains `type.weight.*`, `type.leading.*` and `type.tracking.*` leaves and three `out_of_band` line heights, so its committed outputs drift until recompiled (`compile --check` exits 1). A groups-less import of a ref older than `415be45`, which lacks the three groups, gains the undeclared anchors `type.weight`, `type.leading` and `type.tracking` in its compile report instead, so it drifts too. List the groups explicitly to keep the 0.1.x set.
- **An undeclared leaf's `reason` reaches the report.** `$extensions.qontinui.reason` on an `undeclared` leaf replaces "stated undeclared in the source" in the compile report; a `reason` on any other source, or an empty one, exits 2 (0.1.x ignored it).
- **New flags:** `validate-guide --storage-state <file>` (passed to the wrapper; a file that is unreadable, or is not a JSON object with `cookies` and `origins` arrays, exits 2) and `--json <file>` (`schema: 1`; written on exit 0, 1 and 3, with the `unknown(...)` reason and null for everything a run that stopped before evaluating never reached; a run refused with exit 2 first removes an earlier report at that path too, unless the argv names no resolvable report: `--root` or `--json` with no value or an empty one, either spelled `--root=<dir>` / `--json=<file>`, or another word before `validate-guide`; a `--json` naming an input, or any file that is not an earlier report, is refused, not removed; a report that cannot be written exits 2 after the verdict is printed). Either flag on another command exits 2.
